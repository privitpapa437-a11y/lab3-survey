# Survey CLI — лабораторна робота №3

CLI-програма на Node.js для перегляду JSON-файлу опитування. Варіант 7 — **«Опитування»**. Для розбору команд використано `commander`; читання файлів і розбір JSON виконуються вбудованими засобами Node.js.

## Вміст проєкту

- `index.js` — реалізація шести можливостей і обробки помилок;
- `data.json` — JSON-дані з лабораторної роботи №1;
- `package.json`, `package-lock.json` — npm-налаштування та зафіксовані версії залежностей;
- `.gitignore` — ігнорує `node_modules/`.

## Перевірка даних

Початковий файл був наданий як `json.1lab.txt`. Його вміст є коректним JSON; для проєкту його скопійовано без зміни даних і збережено під потрібною назвою `data.json`.

Структура має `surveyTitle`, масив `questions` (3 записи) і масив `responses` (2 записи). `respondentName: null` у другого респондента та `answerValue: null` для третього питання є допустимими значеннями JSON, а не синтаксичними помилками. Програма не підміняє ці значення: відсутнє ім’я показує як «ім’я не вказане», а `null` — як відсутню відповідь. Для вибору респондента використовується його порядковий номер у `responses`, починаючи з 1.

Перевірка синтаксису:

```bash
jq empty data.json
echo $?
```

Для наданого файла очікується код `0` і відсутність текстового виводу від `jq`.

## Встановлення і запуск

Потрібні Node.js і npm. У корені проєкту:

```bash
node --version
npm --version
npm install
npm start -- --help
```

Без `--file` програма читає `data.json` з поточної теки. Шлях можна перевизначити глобальною опцією `-f` / `--file`; вона працює з командами програми до або після назви команди. Відносні шляхи рахуються від поточної теки термінала.

```bash
npm start -- --file ./data.json list
npm start -- list --file ./data.json
```

## Команди

| Можливість | Приклад | Призначення |
|---|---|---|
| Загальна: перелік | `npm start -- list` | Стислий перелік питань; `--limit 2` обмежує кількість. |
| Загальна: один елемент | `npm start -- show 2` | Повний JSON-запис питання з `questionId=2`. |
| Загальна: окреме поле | `npm start -- field responses.0.answers.1.answerValue` | Значення поля за шляхом із крапками; індекси масивів нумеруються від 0. |
| Варіант 7: фільтр питань | `npm start -- filter-questions --required --type scale` | Фільтр за обов’язковістю та/або типом. Допустимі типи беруться з даних. |
| Варіант 7: відповіді на питання | `npm start -- answers 3` | Відповіді всіх респондентів на питання з ID 3. |
| Варіант 7: відповіді респондента | `npm start -- respondent 2` | Відповіді респондента №2 разом із текстами всіх питань. Нумерація починається з 1. |

Ще кілька корисних викликів:

```bash
npm start -- list --limit 2
npm start -- filter-questions --optional
npm start -- filter-questions --type freeText
npm start -- answers 1
npm start -- field responses.1.answers.2.answerValue
```

## Обробка помилок

Для неіснуючого файла, некоректного JSON, невідомого питання/респондента/поля, некоректного числа, несумісних фільтрів або помилкового виклику програма виводить зрозуміле повідомлення українською і завершується з ненульовим кодом. Стек викликів користувачу не показується.

Приклади перевірок:

```bash
npm start -- show                 # пропущено обов’язковий аргумент
npm start -- show 999              # невідоме питання
npm start -- show abc              # нечисловий ID
npm start -- list --file missing.json
npm start -- field questions.0.noSuchField
npm start -- filter-questions --required --optional
npm start -- list --unknown        # невідома опція
```

Для перевірки некоректного JSON створіть тимчасовий файл `broken.json` з текстом `{ broken`, виконайте `npm start -- list --file broken.json`, а потім видаліть тестовий файл.

## Відновлення залежностей

`node_modules/` не входить до Git-репозиторію. Переконайтеся, що залежності можна відновити:

```bash
rm -rf node_modules
npm install
npm start -- list
```

У Windows Git Bash команда видалення може бути `rm -rf node_modules`; у PowerShell — `Remove-Item -Recurse -Force node_modules`.

## GitHub та коміти

Методичка вимагає окремий GitHub-репозиторій, локальне ім’я Git у форматі `Ім’я Прізвище lab3` і щонайменше п’ять осмислених комітів. Налаштуйте ім’я **до першого коміту**:

```bash
git config --local user.name "Ім’я Прізвище lab3"
git config --local user.name
```

Рекомендовані окремі коміти за етапами: створення npm-проєкту; додавання `data.json`; загальні команди; команди варіанта 7; документація й фінальна перевірка. Перед здачею збережіть вивід `git log --oneline` і додайте посилання на власний репозиторій до звіту.
